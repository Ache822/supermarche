\begin{abstract}
This document serves as the authoritative technical reference manual and architectural blueprint for the \textbf{Supermarche} web application platform---an everyday on-demand express delivery and household service ecosystem serving major urban hubs across Cameroon (Yaound\'e, Douala, Bamenda, Buea, Kribi, and Bafoussam). Constructed upon React 18, TypeScript 5, Vite 5, Redux Toolkit, Tailwind CSS, Material UI, and \texttt{react-i18next} internationalization primitives, the application employs a dual-context viewport architecture. It seamlessly merges an SEO-optimized, highly accessible public consumer web portal with a high-density, real-time protected Administrative Operations Console. This comprehensive specification details our complete system architecture, directory structures, public consumer features, internationalization pipelines, 14 administrative control panels, granular Permission-Based Access Control (PBAC), real-time WebSocket communication pipelines, non-blocking visitor analytics engine, complete design system specifications, REST API contract catalog, local development workflows, and forward-looking architectural recommendations.
\end{abstract}

\section{Executive Summary \& System Architecture}
% =========================================================================

\subsection{System Vision}
Supermarche bridges urban Cameroonian households with verified service runners, certified cooking gas distributors, prepped fresh market food vendors, and skilled household maintenance technicians. The web application is engineered to perform impeccably across diverse connectivity conditions, supporting both high-speed 4G/5G connections and low-bandwidth 3G mobile networks common across Central Africa.

\subsection{Technology Matrix}
\begin{itemize}
    \item \textbf{Core Framework:} React 18 using functional components, custom hooks, and strict TypeScript 5 contracts.
    \item \textbf{Build Tooling \& Bundler:} Vite 5 featuring LightningCSS minification, automated sitemap generation, and fast Hot Module Replacement (HMR).
    \item \textbf{Internationalization Engine (i18n):} \texttt{react-i18next} (\texttt{locales/config.ts}) providing seamless runtime switching between English (\texttt{en}) and French (\texttt{fr}).
    \item \textbf{Global State Management:} Redux Toolkit (\texttt{@reduxjs/toolkit}) enforcing unidirectional data flow across administrative modules, dispatch queues, transaction ledgers, and catalog state.
    \item \textbf{UI Styling \& Primitives:} Dual-layer design system leveraging custom CSS tokens, Material UI (MUI v6/v7), and utility styling for dark-mode glassmorphic aesthetics.
    \item \textbf{Routing \& Navigation:} React Router v6 (\texttt{react-router-dom}) enforcing strict separation between public consumer routes and protected operational routes.
    \item \textbf{SEO \& Head Metadata:} \texttt{react-helmet-async} orchestrating dynamic canonical links, Open Graph attributes, Twitter Card tags, \texttt{hreflang} multi-lingual headers (\texttt{en}, \texttt{fr}, \texttt{x-default}), and structured JSON-LD schemas (\texttt{LocalBusiness}, \texttt{Organization}, \texttt{WebSite}, \texttt{Service}, \texttt{BreadcrumbList}).
    \item \textbf{Real-Time Communications:} Custom WebSocket engine (\texttt{socketClient.ts}) with automatic heartbeat reconnection and REST fallback polling.
\end{itemize}

\subsection{Dynamic Technical \& Local SEO Engine (\texttt{<SEO/>})}
To dominate search engine indexing both globally and locally across Cameroonian cities, the application incorporates a dedicated SEO manager (\texttt{SEO.tsx} and \texttt{schemas.ts}):
\begin{itemize}
    \item \textbf{Dynamic Metadata Management:} Injects route-specific titles (\texttt{Supermarche | On-Demand Express Delivery \& Everyday Services in Cameroon}), localized meta descriptions, Open Graph cards (\texttt{og:title}, \texttt{og:image}, \texttt{og:url}), and Twitter cards.
    \item \textbf{Localization Header Tags:} Automatically appends \texttt{hreflang} tags targeting English (\texttt{en}), French (\texttt{fr}), and global fallback (\texttt{x-default}).

\subsection{Viewport Scaffolding \& Layout Mechanics}
The Admin Console is engineered specifically for desktop administrative workflows:
\begin{itemize}
    \item \textbf{Screen Viewport Scaffolding:} Main container applies \texttt{height: 100vh} and \texttt{overflow: hidden} to eliminate double scrollbars.
    \item \textbf{Data Table Scaffolding (\texttt{ReusableDataTable.tsx}):} Enforces vertical-only table scrolling (\texttt{overflow-y: auto; overflow-x: hidden}) paired with CSS \texttt{position: sticky; top: 0} headers, maintaining header visibility during deep record scrolling.
\end{itemize}

\subsection{Granular Access Control Architecture (PBAC)}
Security is enforced using a fine-grained Permission-Based Access Control model (\texttt{usePermission.ts}, \texttt{HasPermission.tsx}, and \texttt{PermissionProtectedRoute.tsx}):
\begin{itemize}
    \item \textbf{Supported Permissions:} \texttt{pages:read}, \texttt{pages:edit}, \texttt{users:read}, \texttt{users:manage}, \texttt{support:chat}, \texttt{campaigns:manage}, \texttt{faqs:manage}, \texttt{articles:manage}, \texttt{applications:read}, \texttt{applications:manage}.
    \item \textbf{Super Admin Bypass:} Users possessing \texttt{SUPER\_ADMIN} role or wildcard permission (\texttt{*}) override restriction checks.
    \item \textbf{Declarative Rendering Guard (\texttt{<HasPermission/>}):} Wraps administrative UI elements to conditionally render controls based on active session rights:
\end{itemize}

\begin{lstlisting}[language=TypeScript, caption={Declarative Permission Component Usage}]
<HasPermission permission="applications:manage">
  <Button variant="contained" onClick={handleApproveApplication}>
    Approve Pro Application
  </Button>
</HasPermission>
\end{lstlisting}

\subsection{WebSocket Chat Engine Architecture}
Real-time customer support communication is driven by \texttt{socketClient.ts}:

\begin{lstlisting}[language=TypeScript, caption={WebSocket Singleton Client Architecture}]
export class SocketClient {
  private socket: WebSocket | null = null;
  private listeners: Map<string, Function[]> = new Map();

  public connect(url: string = 'ws://localhost:3000/ws/chat'): void {
    this.socket = new WebSocket(url);
    this.socket.onopen = () => this.emit('status', 'connected');
    this.socket.onmessage = (event) => {
      const payload = JSON.parse(event.data);
      this.emit(payload.event, payload.data);
    };
    this.socket.onclose = () => setTimeout(() => this.connect(url), 3000);
  }

  public sendMessage(sessionId: string, message: string): void {
    if (this.socket?.readyState === WebSocket.OPEN) {
      this.socket.send(JSON.stringify({ event: 'chat:message', data: { sessionId, message } }));
    }
  }
}
export const socketClient = new SocketClient();
\end{lstlisting}

\subsection{Non-Blocking Visitor Analytics Engine (\texttt{useVisitorTracker})}
Website visitor activity is logged seamlessly without impeding main-thread execution:
\begin{itemize}
    \item Generates a persistent \texttt{sessionId} stored in \texttt{localStorage}.
    \item Captures route \texttt{pathname}, document \texttt{referrer}, device category (Mobile, Tablet, Desktop), and UTC timestamp on every route navigation.
    \item Asynchronously posts tracking events to \texttt{POST /api/v1/analytics/track}.
    \item \textbf{Offline Resilience:} If the network or backend is unreachable, tracking payloads buffer locally inside \texttt{localStorage} under \texttt{bb\_local\_visitor\_logs} (capped at 100 entries) and synchronize automatically upon backend reconnect.
\end{itemize}

\section{Engineering Recommendations \& Future Roadmap}
% =========================================================================

To support Supermarche's rapid scaling across Central Africa, the engineering team recommends the following architectural enhancements:

\begin{enumerate}
    \item \textbf{Code-Splitting \& Dynamic Module Imports:} Implement \texttt{React.lazy()} and \texttt{Suspense} for heavy administrative modules (\texttt{VisitorAnalyticsOverview.tsx}, \texttt{ProviderApplicationsPanel.tsx}) to reduce initial vendor bundle size below $500\text{ kB}$.
    \item \textbf{Progressive Web App (PWA) Offline Caching:} Integrate Service Worker caching (\texttt{workbox-build}) to allow field runners in low-connectivity zones to access active order tickets offline.
    \item \textbf{Redis-Backed WebSocket Scalability:} Scale the real-time support engine (\texttt{socketClient.ts}) across multiple backend nodes using Redis Pub/Sub socket adapters.
    \item \textbf{Automated End-to-End (E2E) Test Suite:} Deploy Playwright / Cypress integration tests validating critical booking checkout and admin moderation flows.
\end{enumerate}
